# 04 — Settle the event-sourced session log + agent loop

Type: grilling
Status: resolved

## Question

Design the Rust event-sourced core, matching the settled decision: an append-only `SessionEvent` log as the source of truth for model context, driving a turn/step agent loop with fork, replay, and persistence. "Model-visible means logged" is the invariant.

Decide:

- The **SessionEvent log schema** — the durable event set (`session/event` domain): `turn/*`, `step/*`, `user/message`, `assistant/chunk`, `assistant/message`, `tool/call`, `tool/result`, and how extension adds new model-visible events.
- **`deriveMessages()` projection** — how model history is rebuilt from the log, and how raw `assistant/chunk` preserves replay/UI fidelity.
- The **turn/step flow** — turn open/close, step = one model request + the tools it calls; the waterfall extension points (`agent/pre-step`, `agent/request`, `llm/stream`, `tools/*`).
- **Fork, replay, persistence** — the storage behind the log (rolling file / sqlite / in-memory + durability), session fork boundary, resume transcripts.

Consume the map's Out-of-scope (web UI is out; no UI rendering of cards). Decide the minimal event set the spec locks and the persistence backend.

## Answer

Resolved by grilling (1 round, all decisions accepted) with the dev. The event-sourced session log + agent loop design the spec must document. Consumed the runtime design (03) and the dsh references (`docs/subsystems/session.md`, `docs/agent-lifecycle.md`, `docs/architecture.md`).

- **Q1 — Log fidelity: full-fidelity vocabulary.** Reproduce dsh's core `SessionEventMap`: `turn/start`, `turn/end` (typed `TurnEndReason` — completed/aborted/blocked/error/max-tokens/interrupted), `step/start`, `step/end`, `user/message` (with typed `source`), `assistant/chunk` (raw token-level replay), `assistant/message` (assembled + `usage` + `sourceEventSeqs` + optional `interrupted`), `tool/call` (raw unparsed `arguments` JSON + `callId`), `tool/result` (message + optional `error{name,code}` + opaque JSON `meta`), plus log-only `todo/write`, `request/header` (full `EpochHeader` snapshot), `request/context` (route metadata), `session/end-seed`. Nothing trimmed — this is what makes the "model-visible == logged" invariant cohere. Every event lossless JSON; `seq = log.length` contiguity contracts.
- **Q2 — Append validation & immutability via serde.** A closed typed event enum (serde derives). `Session.append` validates lossless-JSON serializability at the source (reject non-serializable values like the TS non-lossless set), rejects a bad event before the log changes. Committed events are immutable after accept (mirrors dsh deep-freeze); `Session.events` returns an immutable snapshot reused until the next append. The hot path never blocks on I/O — persistence observes asynchronously.
- **Q3 — Surface projection (`deriveMessages`).** Derived model history = fold over surface nodes selected by `surfaceOp` markers. `SurfaceOp` is `append` | `replace{start,end}` (replaces range, shadows those nodes from derivation; `start===end` replaces one). Only the three `SurfaceEventType`s (`user/message`, `assistant/message`, `tool/result`) carry surface metadata; `assistant/chunk` is replay data, skipped in derivation; an **empty-content** `assistant/message` is skipped. `sourceEventSeqs` traces lineage (compaction `replace` cites every shadowed node). Cached per surface node, rebuilt on `replaceGeneration` bump; `deriveMessages()` returns a fresh array of shared frozen messages ($O(\text{new nodes})$).
- **Q4 — Plugin event extension (the Rust-vs-TS seam).** TS declaration-merging is replaced by a two-tier event representation: a **core typed enum** for the known set, plus a **plugin-registered extension registry** for log-only event types — keyed by a runtime `type` string, each entry registering `(fold/derive, validate, is_surface)` and a serializable payload shape. Extension events are log-only (never `SurfaceEventType`, never enter derived history). Consumers switch over the closed core enum and fall through for unknown extension types (mirrors Cordis's "don't assertNever over a merge-extensible map"). This is the deliberate, spec'd seam — not an afterthought.
- **Q5 — Turn/step agent loop, full-fidelity.** Reproduce the flow on the runtime's five dispatch modes: `turn/start` → claim next-step input (+ one queued message) → `agent/pre-step` waterfall (authoritative reject or `enter(messages)`) → `step/start` → `user/message` per entered message → `system-prompt/assemble` → `agent/request` + `llm/stream` → `assistant/chunk*` → `assistant/message` → `tool/call` (logged before execution) → guards → `tools/execute` → `tool/result` → `step/end` → `agent/turn-stopping` (serial terminal, no `next()`) → next step or `turn/end`. A rejected/empty first claim still closes a durable turn that spent no step. `agent/request`, `llm/stream`, `agent/pre-step`, `tools/*` are waterfalls delegating via `next()`; `agent/turn-stopping` is serial. The tool-call classify/dispatch (barriers, bounded rolling pool) is enumerated here as the loop's responsibility; the tools pipeline internals stay in 07.
- **Q6 — fork / replay / persistence.** In-memory `SessionStore` (`ctx.sessions`) as the live store; persistence is a **seam** `ctx.sessionPersistence` subscribed to `session/event` + awaited `session/flush` checkpoint, with a **JSONL backend first** (dsh's default; sqlite deferred). `fork(source, boundary?, childSessionId?)` selects an inclusive prefix required to end **between turns** (rejects a prefix ending inside an open turn rather than clipping), deep-clones seed events + child metadata (`parentSession`, `seedLength`, inherited `cwd`). Crash recovery synthesizes the `interrupted` `turn/end` reason for orphaned open turns on reload. `prepare`/`enter`/`announce` lifecycle folded into one agent effect so a fiber unload tears session+loop down in order.

**Spec locks:** Q1–Q6. **Deferred:** compaction `replace` producers (a later/deferred seam), the tools execution-pipeline internals (07), persistence backend breadth beyond JSONL.
